# 12: Select an option by name in UIA combos and lists

**What to build:** `set-value <combo-or-list> <label>` on a UIA ComboBox or List picks the item with that name. Page `<select>` lists already work this way. agent-desktop's `select` does a bounded descendant search (research section 1, Interaction rows).

- If the Element has a Value pattern that accepts the label (editable combo), keep today's route.
- Otherwise: Expand if collapsed (ExpandCollapse), find the item by exact name (then case-insensitive) in a bounded search, using ItemContainer.FindItemByProperty and VirtualizedItem.Realize for virtualized lists, `SelectionItem.Select`, Collapse, then read the selection back.
- Ambiguous names: refuse, listing the candidates. No match: refuse with "nothing was sent" except the Expand, which is collapsed again ("the list was opened and closed; no item named ...").
- Headless; `--headed` activates first, then the same pattern calls.

**Blocked by:** none

## Comments

### 2026-11-02: landed

- `internal/uia/selectitem.go`: the select route. `selectByName` is the pure driver over `selectSteps` (expandState, expand, collapse, items, findHidden, pick, selected), so the offline tests fake the live calls the way `toggleTo` and `runWithInvokeFallback` do. Order: Expand when the Element reads collapsed; the bounded search's item names; exact match; else `ItemContainer.FindItemByProperty(Name)` for a virtualized list's unbuilt items (a second lookup after the first hit detects several); else the name ignoring case and spacing. Several matches at one rule refuse (`ErrAmbiguousItem`, listing them), none refuses (`ErrNoSuchItem`, listing up to 12 items, `page.OptionError`'s shape). Both are a `SelectItemError`; when the search had expanded the list it is collapsed again and the message starts "the list was opened and closed; " ("...could not be closed again; " when the Collapse fails). Then `VirtualizedItem.Realize` when offered, `SelectionItem.Select`, Collapse when the drop-down is still open, and the read-back (polled 1 s): the container's `Selection.GetCurrentSelection`, else its Value, else the item's IsSelected; a mismatch is a `VerifyError` ("set-value selected "Red" but the list shows "Blue" selected afterwards"). A failed Select that may have taken effect stays a `WriteError`.
- COM bindings in the same file: `FindAll(TreeScope_Children, ControlViewCondition)` breadth-first, 4 levels and 2000 elements at most, keeping up to 1000 SelectionItem Elements (an item's own children are not searched); slots, pattern ids and IIDs (Selection, ItemContainer, VirtualizedItem) checked against the local SDK 10.0.26100.0 `UIAutomationClient.h`. FindItemByProperty's by-value VARIANT is passed as a pointer to a copy, as both the x64 and arm64 ABIs do for a 24-byte struct.
- `internal/uia/value.go`: `setValue` became a wrapper over `writeValue`, which reports whether the select route ran. The route is taken when the Element offers Selection or ItemContainer and its Value pattern is missing or read-only (a drop-down list's Value is read-only); an editable combo keeps the Value write, and nothing changes for edits, sliders and toggles. `SetValueHeadless` skips `verifyValue` when the select route ran (it reads its own selection back, and a case-insensitive pick would not equal the typed label). Headless and `--headed` share the route; Headed focuses first as before, then makes the same pattern calls.
- `internal/helper`: `valueError` hints for ambiguous ("an exact name wins over one that differs only in case or spacing"), no match ("pass one of the list's item names exactly"), and a search that failed after the Expand (keeps the opened-and-closed wording). `refusedBeforeCall` treats a `SelectItemError` as nothing-sent only when the list was not opened, so a list refusal ends "; nothing was sent" and a combo refusal says it was opened and closed.
