# 12: Select an option by name in UIA combos and lists

**What to build:** `set-value <combo-or-list> <label>` on a UIA ComboBox or List picks the item with that name. Page `<select>` lists already work this way. agent-desktop's `select` does a bounded descendant search (research section 1, Interaction rows).

- If the Element has a Value pattern that accepts the label (editable combo), keep today's route.
- Otherwise: Expand if collapsed (ExpandCollapse), find the item by exact name (then case-insensitive) in a bounded search, using ItemContainer.FindItemByProperty and VirtualizedItem.Realize for virtualized lists, `SelectionItem.Select`, Collapse, then read the selection back.
- Ambiguous names: refuse, listing the candidates. No match: refuse with "nothing was sent" except the Expand, which is collapsed again ("the list was opened and closed; no item named ...").
- Headless; `--headed` activates first, then the same pattern calls.

### 2026-11-02: landed

- `internal/uia/selectitem.go`: the select route. `selectByName` is the pure driver over `selectSteps` (expandState, expand, collapse, items, findHidden, pick, selected), so the offline tests fake the live calls the way `toggleTo` and `runWithInvokeFallback` do. Order (as revised in the review below): the bounded search's item names; exact match; else `ItemContainer.FindItemByProperty(Name)` for a virtualized list's unbuilt items (a second lookup after the first hit detects several); else the name ignoring case and spacing. Several matches at one rule refuse (`ErrAmbiguousItem`, listing them), none refuses (`ErrNoSuchItem`, listing up to 12 items, `page.OptionError`'s shape). Both are a `SelectItemError`; when the search had expanded the list it is collapsed again and the message starts "the list was opened and closed; " ("...could not be closed again; " when the Collapse fails). Then `VirtualizedItem.Realize` when offered, `SelectionItem.Select`, Collapse when the drop-down is still open, and the read-back (polled 1 s): the container's `Selection.GetCurrentSelection`, else its Value, else the item's IsSelected; a mismatch is a `VerifyError` ("set-value selected "Red" but the list shows "Blue" selected afterwards"). A failed Select that may have taken effect stays a `WriteError`.

FindItemByProperty's by-value VARIANT is passed as a pointer to a copy, as both the x64 and arm64 ABIs do for a 24-byte struct.

### 2026-11-03: live run, the classic combo never told its app

- Live e2e (`TestSetValueSelects*`, first run): the Item List passed; the Classic Dialog combo test failed at line ~72. `set-value <dialog> id:1003 Green` printed `ok`, but the fixture never recorded `classicColor`, which it records only on WM_COMMAND/CBN_SELCHANGE. A programmatic selection (CB_SETCURSEL, LB_SETCURSEL) notifies nobody, so an app that reacts to CBN_SELCHANGE never saw the change.
- Diagnosed with temporary helper-log lines, since removed. The Win32 combo proxy was not doing what the ticket assumed:
  - The proxy reports the drop-down list's Value **writable** and offers neither Selection nor ItemContainer. set-value never reached the select route: it took the Value write, and the read-back matched. Its Value is the window caption, not the selection: it read `""` after a real CB_SETCURSEL.
  - Once routed to the select route, the proxy exposed **no items while collapsed**. The route therefore expanded the combo.
  - Expanded, the combo's control-view children included the ComboLBox **and every top-level window on the desktop** (taskbar, the user's other apps). The bounded search read their names and found the fixture main window's Item List twice.
  - The pick took (CB_GETCURSEL read 1 for 150 ms), but the Collapse after it cancelled the pick: the combo restored its old selection (-1). The proxy's `SelectionItem.Select` on the ComboLBox item did not move the closed combo's selection either.
- Changes:
  - `internal/win/selnotify.go` (new): `NotifySelectionChange(hwnd)` sends `SendMessageTimeout(GetParent(ctl), WM_COMMAND, MAKEWPARAM(GetDlgCtrlID, CBN_SELCHANGE or LBN_SELCHANGE), ctl)`. It notifies a classic ComboBox, a ListBox only with LBS_NOTIFY, and a ComboBoxEx32 through its inner combo (CBEM_GETCOMBOCONTROL; the ComboBoxEx forwards it). Any other window gets nothing. It is guarded by `LiveDesktopGuard`, uses keyroute.go's `sendMessageTimeout` and `ReadControl`, and has a 2 s timeout.
  - The same file adds the combo's own messages: `ComboItems` (CB_GETCOUNT, CB_GETLBTEXTLEN, CB_GETLBTEXT), `SelectComboItem` (CB_SETCURSEL, guarded) and `ComboSelection` (CB_GETCURSEL). It also adds `Control.Combo`, `Control.DropDownList` and `WithinControl` (the control, its child windows, or its GetComboBoxInfo drop-down list).
  - Only CBN_SELCHANGE is sent, not CBN_SELENDOK first. A user's pick from the open list also sends CBN_SELENDOK and CBN_CLOSEUP, but CBN_SELCHANGE is the one apps act on, and a second message is a second chance to act twice. Revisit if an app needs SELENDOK.
  - `internal/uia/selectitem.go`: `selectSteps` gained `notify`, which `selectByName` calls once, last, only after the read-back passes. A refusal, a failed Select or a failed read-back notifies nothing. A failed notification is a `VerifyError` ("set-value selected "Red", but telling the app about the change failed (...)"), so the helper reports the Action as delivered ("do not repeat it"), never "nothing was sent".
  - A classic ComboBox (the Element's NativeWindowHandle has class ComboBox) runs the same driver over `classicComboSteps`. That binding reads the items by CB_GETLBTEXT, never opens the combo, picks with CB_SETCURSEL (a failure is a `WriteError`: it may have taken effect), reads back with CB_GETCURSEL (polled 1 s), and sends CBN_SELCHANGE.
  - Every other Element keeps the UIA binding, now with the notify step, so an LBS_NOTIFY ListBox or a ComboBoxEx32 still gets notified. The UIA binding's bounded search skips any descendant whose own window is outside the Element's window (`win.WithinControl`), so an opened Win32-hosted combo no longer walks the desktop.
  - `WriteError` gained `Err` for a window message's failure.
  - `internal/uia/value.go`: a classic drop-down list (`CBS_DROPDOWNLIST`) takes the select route although its Value reads writable. Editable classic combos keep the Value write.
  - `nativeWindow(el)` was factored out of `ElementWindow`.
